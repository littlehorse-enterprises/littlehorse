# LittleHorse 1.3.1

LittleHorse 1.3.1 is a focused patch release that improves task recovery, bulk job stability, and resilience during Kafka broker restarts. It also fixes sleep node processing, speeds up initial task worker registration retries across SDKs, and corrects Go workflow control flow and child workflow input display in the dashboard.

## Bug Fixes

### Server

- Scheduled task recovery now scans for pending tasks older than the persisted queue hint, preventing tasks from being skipped after partition reassignment or server restart. Claims for task runs that no longer exist now return an empty response. #2587
- Background jobs now stop cleanly when Kafka Streams enters pending shutdown, avoiding unnecessary error stack traces. #2579
- Matured sleep nodes are now processed correctly when their thread IDs exceed the size of the active thread list after completed threads have been archived. #2540
- Getable size validation now uses a stable snapshot of pending changes, preventing concurrent modification errors while validating related objects. #2529
- Bulk job shard progress reports are now limited to once per minute, reducing load on the metadata processor. Pending reports are preserved across partition handoffs. #2523
- Reduced the Kafka request timeout to allow more retries before a transaction times out, improving resilience during rolling broker restarts. #2526

### SDKs

- Java, Go, Python, .NET, and JavaScript/TypeScript SDKs: task workers now retry failed initial registration attempts after approximately one second, reducing startup delays when the server is temporarily unavailable. #2584
- Go SDK: fixed `DoWhile` workflow generation when the condition is initially false, allowing execution to continue past the loop. #2561

### Dashboard

- Child workflow input names now retain space beside their values, with the full name available in a tooltip when truncated. #2567
