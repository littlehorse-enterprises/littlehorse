# LittleHorse 1.4

LittleHorse 1.4 adds inline workflows that run without a registered `WfSpec`, Struct-backed user tasks, and mutually exclusive Struct fields through `OneOf` groups. This release also redesigns workflow diagrams, expands Java workflow authoring and authentication options, and improves server search performance, observability, and storage configuration.

These notes describe changes from `v1.3.2` to `master`; fixes already included in `v1.3.2` are omitted.

## Features

### Server

- Added `RunInlineWf` and `GetInlineWfSpec` for executing durable workflows without first registering a `WfSpec`. The validated definition is stored alongside its owning `WfRun` and deleted with the run, including retention-based cleanup. Referenced TaskDefs and other metadata must still be registered. #2575
- Added Struct-backed user tasks with a registered `StructDef` as their output contract. Submissions support nested typed data, field masking, and partial progress saving. Each new `UserTaskRun` pins the latest available version of its result StructDef when it is created. #2614
- Added flat Struct `OneOf` groups through `StructFieldDef.oneof_group`. Fields in the same group allow zero or one selection, with validation for submitted values, Struct builders, saved user task progress, mutations, and schema evolution. #2639, #2648
- Added `PutVariable` to replace an existing workflow variable, return its previous value with masking applied, and attempt to advance the workflow. Sleep nodes can recalculate their wake-up time when a referenced variable changes. #2581
- Expanded `LHS_ROCKSDB_*` settings for compaction, compression, background and flush threads, write buffers, file sizing, and write throttling. Administrators can tune RocksDB for their workloads. #2589
- Added support for custom OAuth certificate authorities through `LHS_OAUTH_CA_CERT`, which accepts a PEM file and supplements the default trusted CAs. #2617

### SDKs

- Java and Go SDKs: added inline workflow builders using the existing workflow thread APIs, with optional run IDs and retention policies. #2575
- Java, Go, and .NET SDKs: added schema helpers for registering Struct-backed user tasks. Updated Java, Go, Python, and .NET examples demonstrate typed forms and submissions. #2614
- Java SDK: Java records can now define StructDefs and serve as typed task inputs and outputs, including record component annotations and serialization through the canonical constructor. #2295
- Java SDK: workflow factories now accept `LHConfig` before compilation so configured type adapters participate in workflow type resolution. #2593
- Java SDK: added `Workflow.getReferencedJavaTypes()` to inspect classes discovered while compiling a workflow. #2550
- Java SDK: `LHConfig` now accepts custom gRPC `ClientInterceptor`s through constructors and its builder, enabling client-side metrics, logging, and other call instrumentation. #2358
- .NET SDK: added chainable `Get(field)` accessors on node outputs and workflow variables for selecting Struct and JSON object fields. #2614
- Java, Go, Python, .NET, and JavaScript/TypeScript SDKs: added `LHC_OAUTH_CA_CERT` to trust additional PEM certificate authorities for OAuth requests. #2617

### Dashboard

- Redesigned workflow diagrams with consistent node styling, improved layout and loop routing, clearer branch labels, and condition details alongside edge mutations. Runtime condition details can display task output values. #2554
- Added details and thread navigation for `SpawnThreadForEach`, including the input collection and per-thread input assignments. #2562
- Running workflow durations now update live. #2559
- Task node details now display input parameter names. #2564
- Checkpoint values and logs can now be expanded in the output modal. #2552
- Workflow and task metrics now include manual refresh controls. #2551
- Added Struct-backed user task output and saved-progress displays, plus result StructDef links and fields on UserTaskDef pages. #2614, #2643

### `lhctl`

- Added `lhctl execute task <taskDefName>` to invoke a registered task through an inline workflow, using positional inputs or repeated `--arg name:value` flags. Inputs are converted using the TaskDef's declared types, including Struct inputs. #2575
- Added `lhctl get inlineWfSpec <wfRunId>` to inspect a run's inline definition. #2575
- Added `lhctl put variable` to replace an existing workflow variable and print its previous value. #2581
- Struct-backed user tasks support interactive typed form entry and JSON submissions through `--resultFile`, including partial progress saves. #2614
- `lhctl login` now uses PKCE with S256, supporting identity providers that require proof of key exchange. #2632
- Added `LHC_OAUTH_CA_CERT` support for OAuth login and token requests against providers using private certificate authorities. #2617

## Performance And Observability

- Eligible workflow searches now use searchable string variable indexes to narrow candidates instead of scanning all runs of a WfSpec. Version, time-range, and parent-scoped searches retain the existing scan path. See the known limitation below for historical index coverage. #2602
- Added gRPC server processing-duration histogram buckets through `grpc_server_processing_duration_seconds_bucket`, enabling percentile calculations across server instances. Streaming RPC durations cover the lifetime of the stream. #2645

## Bug Fixes

### Server

- Edge mutations now validate the final values of all changed variables against their declared types before committing changes. This rejects invalid Struct, Array, and Map contents and nulls in non-nullable Struct fields, and applies masking metadata to Struct fields written through paths. #2641, #2648

### SDKs

- Java SDK: configuration defaults are initialized atomically, preventing concurrent workers sharing an `LHConfig` from receiving inconsistent generated worker IDs. #2618
- Go SDK: properties-file configuration now reads the OAuth callback port from `LHC_OAUTH_CALLBACK_PORT`. #2615
- Python SDK: checkpoint callbacks that return awaitables are now awaited before their results and logs are persisted, including synchronous wrappers around asynchronous callbacks. #2612

### Dashboard

- Workflow diagrams now load all pages of NodeRuns, preventing large workflows from displaying incomplete execution details. #2554
- UserTaskDef pages now load the requested version and link to the correct route when switching versions. #2643
- Integers nested in Structs, Arrays, and Maps retain their exact values when displayed, including values beyond JavaScript's safe integer range. #2643
- User task sidebar caches now include the WfRun ID, preventing results, assignments, and events from another workflow from appearing while data loads. #2643

## Dependencies And Upgrade Notes

- Updated the server's Kafka Streams dependency from `4.3.1` to `4.4.0`. #2591
- Standardized dashboard and JavaScript SDK development tooling, along with dashboard container runtimes, on Node.js 24. The published JavaScript SDK retains its consumer requirement of Node.js `>=18.14.0`. #2578
- Updated Python SDK `certifi` and JavaScript dependencies including `protobufjs`, `sharp`, and `brace-expansion`. #2640, #2515, #2518, #2652
- Legacy field-backed user tasks remain supported, but `UserTaskField`, UserTaskDef `fields`, and user task `results` maps are deprecated. New Struct-backed integrations should use `result_struct_def_id` and `output`. Saved Struct progress replaces the previous saved output; completion must submit the complete form. #2614
- Java workflow factories without `LHConfig`, and `compileWorkflow(LHConfig)`, are deprecated. Pass the config to `Workflow.newWorkflow(...)` and then call `compileWorkflow()`. #2593
- Inline WfRuns use the `is_inline` member of `wf_spec_source` instead of `wf_spec_id`. Clients inspecting runs should handle both sources and use `GetInlineWfSpec` for inline definitions. #2575
- RocksDB settings that previously had LittleHorse-specific overrides now generally retain the underlying defaults unless explicitly configured. Review storage tuning when upgrading, especially compaction style, compression, and background thread settings. #2589

## Known Limitations

- Indexed workflow searches can omit historical runs whose variables were not indexed if the older, non-indexed WfSpec definition has been deleted. Historical index coverage remains unresolved. #2602
- Struct `OneOf` support in this release covers the protobuf schema and server enforcement. The higher-level SDK annotations and helper types described in the OneOf proposal are not yet implemented. #2639, #2648
